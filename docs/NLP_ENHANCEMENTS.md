## 能力与实现

| 能力 | 实际行为 | 主要实现 |
|---|---|---|
| 意图与证据抽取 | 区分时间、金额、条件、借期、数量、专业、电话等；抽取实际证据原句与编号 | `query_understanding.py`、`evidence.py`、`direct_extractor.py` |
| 多轮指代与省略恢复 | 只采用最近用户问题的明确对象；不采用模型回答作为事实；新主题是上下文屏障 | `query_understanding.py`、Web / CLI 历史 |
| 扩大召回和精排 | 两路各召回至少30块，关键词/语义按0.35/0.65加权RRF；增加专题候选与证据精排，同节最多两个候选 | `hybrid_retriever.py`、`evidence.py` |
| 简称与错字 | 最长别名优先；明确错字自动归一化，模糊词给建议；借阅中的教师称呼归一化 | `query_understanding.py` |
| 分块与补全 | 按句、段落和一至三级标题分块；保存同节有界上下文、来源与稳定章节编号，补全原句及适用条件 | `document_loader.py`、`evidence.py` |
| 答案评测与拒答 | 验证参考事实、引用编号、证据连接和数字；未知事项拒答、代词不明时澄清 | `answer_evaluate.py`、`answer_dataset.json` |

规则精排与意图识别是本地、可解释的启发式实现，并非新训练的分类或排序模型。可选交叉编码器由 `RAG_RERANKER_PATH` 指定本地模型目录；未配置、加载失败或推理失败时回退规则精排，并在结果中标明实际方式。本次验收使用默认规则精排，没有下载或验证额外精排模型的效果。

## 从输入到答案

1. 校验请求与历史长度，执行安全检查。
2. 归一化用词，识别主题、问题类型，必要时恢复省略对象；歧义时直接澄清。
3. 导航问题继续走原来的地图链路；问答问题进入双路检索与专题候选精排。
4. 展开同章节上下文，按所问事件、对象和事实单位筛选证据。
5. 只保留实际引用的资料块，对原句重新编号，返回核心解答和逐句证据。
6. 无对应事实则拒答。可配置的生成模型仅接收选中的证据，不能逐句核验的输出回退为原句。

模型润色校验故意保守：包含新增解释或无法与原句及编号匹配的内容会被舍弃。它不是完整的语义蕴含模型。答案评测显式关闭生成模型，不使用环境变量中的 API Key 发起外部生成请求。

## 修复的具体问题

- 奖学金“截止”不会再命中选课的固定回答。
- 本地资料中的22:00闭馆与21:30停止借还业务分别保留；没有沿用旧代码写死的8:00/21:30答案。
- 借阅期限不会拿24小时值班或新闻里的每周开放70小时作答；借书额度不会拿捐赠图书册数作答。
- 奖学金发放时间与申报时间分别按“发放/划拨”“截止/提交”关系判断。
- 普通图书借期与续借规则区分，教师借书额度按教职工类别处理；资料未覆盖的研究生借额不套用本科生规则。
- 明确年份、对象或事项缺失时不拿相邻政策代替，例如未来翻新预算、馆长手机号、未收录的学费金额。
- 学院的三级标题独立分节，避免把其他学院的专业、网址或电话带进当前上下文。
- 切块或语料中段变化会使缓存失效；缓存同时检查模型/配置指纹、维度、数值类型和有限值。
- 清空会话会清除上下文并中止正在等待的浏览器请求，旧结果不会重新填入新会话。
- 来源链接的普通URL匹配不会再因缺少正则捕获组导致接口异常。

## 使用和查看

直接运行 `python main.py --web --port 8000`，或使用原来的启动脚本。打开页面后可以按顺序询问：

1. “图书管晚上几点关门？”
2. “那周末呢？”
3. “奖学金申请什么时候截止？”
4. “晴川奖学金一等奖多少钱？”、“那二等奖呢？”
5. “计院有哪些专业？”
6. “图书馆馆长手机号是什么？”

每条回答有可展开的“问题类型 · 依据状态”区域，展示实际问句改写、用词调整和采用的证据。点击顶部“评测报表”，先显示答案级检查摘要，再显示原有检索级指标。报表读取已经完成的本地结果，不会在点击时启动模型评测。

API新增可选 `history`，最多12条，每条由 `role`（user/assistant）和 `content`（最多1000字符）组成。浏览器发送最近用户问题，服务端不会共享不同浏览器的全局会话。

响应保留原有字段，新增 `query_analysis`、`refused`、`clarification`、`evidence_status` 和 `evidence`。`evidence[].citation_index` 对应 `citations[].index`，引用中的 `evidence_text` 是实际用于回答的文本。启发式评分不是概率，不展示为百分比置信度。

## 本次运行结果

运行环境：Windows、本地既有 PyTorch 环境、CUDA、项目内 BGE-small-zh-v1.5。新切块数为29,427，每个向量512维；索引已重建并验证缓存可复用。

最终答案评测共43题：33道可回答题、7道未知事实题、3道歧义题。

| 模式 | 总通过数 | 可回答题通过数 | 未知事实拒答 | 歧义澄清 |
|---|---:|---:|---:|---:|
| TF-IDF | 31/43 | 21/33 | 7/7 | 3/3 |
| BGE | 39/43 | 29/33 | 7/7 | 3/3 |
| Hybrid | 43/43 | 33/33 | 7/7 | 3/3 |

结果文件：`eval/answer_eval_results.json`。每题包括原问题、历史、输出、引用、证据、参考事实覆盖和是否通过，失败题不会被隐藏。

“通过”要求参考事实在回答和链接证据中出现、来源标识符合标注、编号有效、数字有对应依据，以及拒答/澄清决策正确。来源标识允许指定多个可接受来源中的任意一个，也支持必须同时覆盖的来源清单。它是词面事实与链接检查，不能识别所有逻辑、否定或语义错误。该题集也参与了实现调试，属于回归集，不是独立盲测，43/43不能外推为真实问题100%准确率。

原有26题检索级评测也已重新运行，输出 `eval/eval_results.json`。它按目标知识库类别的首次命中计算指标，某些同样正确的其他来源不算命中；其MRR截断在前5条，NDCG实现按首次目标命中的单相关项假设计算。因此它与新的答案级通过率不能直接比较，也不能把知识库命中率称为答案准确率。

## 数据与适用范围

本次没有替换或重新核实学校事实语料；系统只能根据项目本地资料回答。官网政策更新、资料之间冲突、未列出的别名和复杂省略问句仍需进一步核验。后续应加入独立人工标注的盲测题、更多不可回答问题和新政策版本，按错误类型继续校准规则或训练模型。
