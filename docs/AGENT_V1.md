# 校园办事智能体第一版

## 使用

仍可双击 `start_web.bat`，或在项目目录运行：

```powershell
python main.py --web --port 8000
```

普通问答、三种检索方式、语音、历史记录、来源引用与3D地图保留。右侧新增“普通问答 / 智能办事”开关，两个模式分别保存会话、消息和输入草稿。

1. 在“大模型接入配置”中配置兼容Chat Completions的云端服务与Key，或启用本地Ollama并选择模型。
2. 切换“智能办事”，输入完整任务，例如“从南大门出发去图书馆还书，先查询借还时间，再安排示意路线”。
3. 展开回答下的“执行轨迹”，查看模型选择的工具、校验后的参数、状态、结果摘要和停止原因。
4. 点击“导出本次记录”下载包含答案、引用和工具轨迹的JSON；原有Markdown导出也包含本轮轨迹。
5. 顶栏“数据库历史”根据当前模式打开对应历史。智能办事提供会话列表、对话详情、继续对话和删除会话；离线检查仅保留为开发验证。

没有配置模型时，智能办事明确提示配置缺失，不调用本地规则伪装自主模式。普通问答仍支持无Key运行。新模式使用独立决策请求，输出结构化动作，暂不使用原问答的“思考模式”开关。

## 实际执行方式

模型收到任务、当前会话的有限历史和工具定义，自主返回一个动作：

- `tool`：指定工具名称和参数；执行器检查白名单及参数后调用工具，再把观察结果交回模型。
- `clarify`：缺少起点或其他用户条件时追问。
- `finish`：根据任务生成带证据关联的办理步骤与注意事项，单独标记未确认事项。

循环最多8次决策，总响应预算90秒。工具错误、无效JSON和重复调用都有限制。单次模型传输还有独立超时；执行器使用有界线程池限制在途工作。网络或计算超时后，正在执行的底层工作不一定能立即强制取消，但不会继续无界排队，也不会把迟到结果写入已清空的会话。

智能办事的最终回复分为“办理建议、注意事项、待核实事项”。模型根据本次工具结果生成自然语言步骤，并给每项绑定证据。系统检查引用是否存在、数字是否有依据、常见时间与业务是否对应，以及部分条件和措辞。未通过时允许模型修正；仍未通过则只展示已查到依据，明确方案未完成。不会默默将证据清单作为完整的办事方案。

这些检查是规则护栏，并不能证明每句话在语义上完全正确，复杂否定、条件范围和行程可行性仍需人工复核。规划建议也不代表已代办或提交申请。资料引用不证明政策仍然有效，示意路网不能支持实测距离或未来通行判断。普通问答的生成方式与界面不变。

## 四类只读工具

| 工具 | 实际来源 | 限制 |
| --- | --- | --- |
| search_knowledge | 原有RAG检索与证据抽取，禁用嵌套生成 | 未找到明确证据时返回缺失，不能据此补造政策 |
| lookup_place | 3D地图内置地点与校园别名 | 机构办公室不等于建筑，未记载时不能猜楼栋 |
| plan_route | 原地图道路算法与项目打包布局、建筑障碍 | 仅示意路线，不输出实测距离或实时通行结论 |
| current_time | 主机时间，转换至Asia/Shanghai | 不是学校业务开放状态查询 |

路线工具需要Node.js。可用 `CAMPUS_NODE` 指定其可执行文件，否则使用PATH中的node。地图布局由项目文件读取，不含当前浏览器localStorage里的自定义编辑；页面中的红线可能因自定义布局而不同。没有道路、接入失败、网络不连通或未知地点时返回具体状态。湖泊中心不作为步行起终点。

## 会话与数据

新模式数据保存到 `data/campus_agent.db`，不改变原 `qinchuan_rag.db` 的表结构。按session_id组织运行记录，服务端读取本会话历史，忽略请求携带的任意history，避免把另一个页面会话的文本当作本会话记忆。

清空聊天会清理当前智能办事历史并切换新会话标识。后台用会话版本号阻止在途结果恢复已清空的数据。数据库历史删除接口也同步清理对应智能体记录。版本号和会话标识不是用户身份认证；第一版供本机演示，不是已完成多用户权限管理的生产部署。

轨迹保存操作与结果摘要，不保存模型内部思维链或请求Authorization。已知凭证字段、JSON凭证和Key样式字符串会脱敏，无效工具参数不原样回显。不能保证识别任意格式的个人信息，仍不应输入私人资料。采用云端服务时，用户任务、相关历史与已选证据会传到所配置的模型端点。

## 质量检查

```powershell
# 固定脚本决策与示例工具，检查执行器边界，不产生模型费用
python eval/agent_evaluate.py

# Python回归与界面逻辑
python -m unittest discover -s tests -v
node --test tests/test_chat_ui.cjs tests/test_agent_ui.cjs
node --check web/static/js/agent.js

# 显式真实云端模型评测：需要环境变量DEEPSEEK_API_KEY，可能产生费用
python eval/agent_evaluate.py --live --model your-model --api-url https://your-endpoint/v1
```

离线结果写入 `eval/agent_offline_results.json`，包括工具观察、错误参数、未知工具、拒绝自由编造答案、异常恢复、重复调用和停止边界。单元测试另覆盖会话隔离、清空版本、脱敏、实际地图算法和云端/Ollama的本地HTTP传输契约。

真实评测题目在 `eval/agent_dataset.json`，结果写入独立的 `eval/agent_live_results.json`。必须配置真实模型并显式执行才生成；每题记录工具轨迹，所需工具是否出现和引用关联只是代理检查，事实条件与任务完成需要人工复核，不自动宣布“准确率”。

浏览器UI样例响应和本地脚本HTTP服务仅用于验证界面、传输与接线，不能作为真实模型自主决策效果的证据。参赛材料应清楚区分：执行器测试、真实模型运行、人工复核与已发现缺陷。

## 接口

- `POST /api/agent/chat`：配置字段沿用原聊天请求，session_id必填。
- `GET /api/agent/sessions`：最近100个已保存的办事会话摘要。
- `GET /api/agent/runs?session_id=...&limit=200`：读取本会话记录，默认30条，最多200条。
- `DELETE /api/agent/runs?session_id=...`：清空本会话智能体历史。
- `GET /api/agent/quality`：读取已保存离线检查结果。
- `POST /api/agent/quality/run`：只运行固定离线检查，不允许从请求注入生产工具故障。

原 `POST /api/chat` 保持普通问答；现有 `DELETE /api/history` 同步清理智能体数据。通过原端口 `/docs` 查看新增接口。

## 普通问答与智能办事的对话隔离
两个模式分别持有消息节点、会话标识、上下文、草稿、输入历史、引用映射与上一问快照。切换时保留节点，因此展开的依据或执行记录也能恢复。新建与清空仅作用于当前模式；进行中的请求禁止切换。普通问答沿用原界面和回复渲染，智能办事使用独立任务卡片，不显示普通问答的检索标签、实体分析或消融对比。地图与模型配置仍共用。普通会话标识保留原存储键，办事使用独立存储键。
