# 复合问题、事实槽位、检索按钮与 DeepSeek V4.1 Flash

更新：2026-10-21。此文记录在原六项 NLP 增强上的追加改进。

## 现在可以怎么问

- “图书馆和实验室分别几点关门？” → 分别查证两个地点。
- “图书馆几点闭馆，一次最多能借多少本书？” → 分别回答时间和借阅数量。
- “图书馆在哪里，咨询电话是多少？” → 位置和电话均有对应依据。
- “奖学金一等奖和二等奖各多少钱？” → 每个等级单独匹配金额，不能用奖金总额代替。
- “图书馆在哪里以及咨询电话是多少？” → 支持自然连接词与连续问号等分句方式。
- “奖学金一等奖多少钱，二等奖呢？” → 继承主题和金额属性，保留各自等级条件。
- “图书馆几点闭馆，馆长手机号是多少？” → 正常回答有依据的部分，并明确指出另一部分缺少依据。

每次最多支持6个子问题；超出时明确提示分批提问，不静默截断。多个对象后的单独代词仍可能需要澄清。拆解使用本地规则和校园实体表，并非覆盖所有中文句法的通用解析器。

## “对象—属性—条件”具体是什么

问句会输出结构化 `query_analysis.slots`，例如“图书馆老师借阅上限是多少”：

```json
{"subject":["图书馆"],"attribute":"quota","conditions":{"role":"教职工"}}
```

“多少本”“几册”“借阅上限”等表达统一到借阅数量属性；奖学金等级、读者类别、申报/发放事件作为条件参与证据判断。金额必须对应所问主体和等级，不能拿同一段的其他金额、人数或总额代替。

时间问题要求对应开放/关闭关系和时间值，位置问题要求实际位置关系，而不是仅含“时间”“室”“规定”的段落。同专题的规章和服务资料有明确相关事实时，优先用于稳定事实问答；相关新闻不能仅因提到同一地点而抢占结果。这不解决所有政策时效或资料冲突问题，仍须核验原始资料。

每个子问题独立检索、校验，再合并引用并重新编号。同章节引用合并时会合并实际证据，而不是覆盖掉其他子题的证据。响应新增 `sub_answers` 和 `partial`，展开问句分析可以查看拆分查询及逐项状态。

## 导出前面的三个按钮

| 按钮 | 用途 | 适合比较的情况 |
|---|---|---|
| 混合检索与精排 | 结合关键词和语义召回，再按事实证据排序 | 默认使用，综合比较 |
| BGE 稠密语义 | 按句子的语义查找资料 | 换说法、近义表达 |
| TF-IDF 统计词频 | 按字符词频和字面相似度查找资料 | 明确名称、关键词匹配 |

它们控制“怎样找资料”，DeepSeek 控制“怎样基于资料生成答复”，两者独立。切换按钮会立即更新高亮、可访问选中状态和说明，但不会自动重算已经显示的旧答案，也不会自动发出付费生成请求。

**对下一次提问生效。** 想比较同一个问题时，点击新增的“用当前方式重新回答上一题”。该按钮使用上一题当时的历史上下文，不把上一题自己重复塞进上下文。每条答复会标注本次检索方式、所选生成模型和实际回答提供方。

此前的选中状态错误来自用按钮文字匹配内部名称：`TF-IDF` 与 `tfidf` 不同，中文混合按钮也不包含 `hybrid`。现在改用独立的 `data-mode` 标识。请求进行时禁止修改模式和模型配置；清空会话同时重置重答记录。

导出记录新增检索方式、实际提供方和模型回退原因，不包含 API Key。

## 接入你要用的 V4.1 Flash

官方接口的模型名为 **`deepseek-flash`**，显示名称为 DeepSeek V4.1 Flash。原先界面的 V3 / R1 配置已移除，旧浏览器配置会迁移为 Flash，保留原有 Key。模型名和思考开关按 [DeepSeek 更新说明](https://api-docs.deepseek.com/updates/) 与 [思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 核对。

1. 打开顶部“DeepSeek 大模型配置”。
2. 填入自己的 API Key，模型保持“DeepSeek V4.1 Flash（deepseek-flash）”。
3. 思考默认关闭；如需启用，勾选独立的思考开关。
4. 保存后再提问，根据答复顶部的“实际提供方”和生成状态判断是否实际使用了模型。

保存配置只保存当前浏览器的设置，不自动做连接或余额测试，所以会显示“未验证连接”。Key 保存在当前浏览器本地存储中，不进入导出文件。

客户端固定使用官方 `https://api.deepseek.com/chat/completions`，显式发送 `thinking.type=disabled/enabled`，只使用最终 `content`，不把 `reasoning_content` 当作答案。非思考输出预算2048，思考输出预算8192；不自动重试请求。

认证失败、余额不足、模型不可用、限流、超时、非JSON响应或输出截断会返回安全的中文状态并回退本地答案，不输出 Key 或服务端原始错误体。模型输出必须与完整证据单元一致，不能删掉“不”、读者类别或前置条件；证据校验失败时同样回退。

复合问句最多调用一次生成模型，不按子问题分别调用。部分问题缺少依据时保留逐项本地答复，不为该复合问题调用生成模型。无 Key 时全部本地问答功能仍可运行。

## 2026-10-22 文章阅读修正

- 模型请求现在同时包含命中文章正文和定位证据；定位句不再是模型唯一能看到的内容。
- 一般咨询/FAQ 问题在本地抽取前展开文章上下文，排除纯问题句、同名标题和知识库目录说明；学校性质问题匹配描述学校性质的事实句。
- 生成答案按所引文章正文核验，而非仅按先前抽中的核心句核验。引用仍需对应来源，数字和否定条件仍检查。
- 无分隔符的文章不再静默截断为1500字。
- 新增5个回归测试；完整Python测试120项通过。模型请求内容使用模拟接口验证，未使用真实Key发起付费调用。


## 2026-10-22 简短主题检索与来源覆盖

## 2026-10-22 三篇阅读与近期内容优先

本条替代前述简短主题“先按发布日期排序”的行为。文章咨询先按检索相关性排名，按原文URL去重，展开正文验证相关性后选择前三篇（不足三篇按实际数量），再让生成模型读取这三篇完整正文及发布日期。前端将来源数标为“篇阅读文献”，区分“答案引用”和“阅读参考”。

默认本地备用答案优先取所选文章中发布日期最新且有相关证据的文章；没有日期则保留相关证据，不编造日期。模型提示词要求结合正文事件时间判断，区分不同届次；数字与引用校验继续启用。指定年份或要求历史对比时，不应用默认最新日期限制。新闻较新不代表已在所有官网资料中验证为最新。


## 2026-10-22 部分匹配失败仍调用模型

原先复合问题 partial=True 会直接返回 skipped_partial，且有些子问题在规则抽取失败后丢失阅读来源。现取消此拦截：相关资料存在且配置模型时，无论本地规则是否完整匹配，均发送原文让模型逐项回答；复合问题只调用模型一次。阅读资料统一补充至三篇，不把每个子问题的资料重复叠加；同一原文URL的证据合并。

移除“必须逐字复述所有本地证据”的复合答案门槛，改为检查子问题对象/等级覆盖，并继续检查事实引用、数字和否定条件。允许单独明确说明某项未记载。模型可从全文补充本地规则没有提取出的事实；没有原文依据的内容仍不得编造。

文章展开按同级或上级标题停止，避免没有横线分隔符时把整份汇编发送给模型。界面显示本次生成请求实际附带的原文数量，并区分本地规则判断和模型阅读结果。


超长汇编不会作为普通文章补充阅读。已有必要证据若来自超长文档，生成请求保留证据附近最多16000字符上下文，并显式标记context_kind为“原文上下文节选”；普通文章保留全文。这避免输入整份分类汇编导致上下文过大，不能把节选描述为已阅读整份汇编。
